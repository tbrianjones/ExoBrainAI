## Summary

Every AI application being built today is converging on the same pattern: aggregate relevant knowledge, centralize it securely, enable AI to search and synthesize context, and interface with humans and other systems. The human has become just another entity in the knowledge graph, another API endpoint. This convergence points toward a fundamental reinvention of personal computing: computers as "exo-brains," locally-controlled personal knowledge systems where ideas live, evolve, and interface with the world through natural language.

## Origin

Observation of a universal pattern across all AI startups and enterprise implementations: they're all building the same infrastructure (knowledge aggregation, secure centralization, context synthesis for LLMs, multi-interface connectivity), just applied to different verticals. This suggests we're not building discrete applications but rather discovering a new computing paradigm.

## Core Concepts

### The Convergence Pattern

Every AI application follows the same blueprint:
1. Aggregate all relevant information (business processes, customer data, team knowledge, documents)
2. Centralize it securely
3. Implement access controls (who can see what, which agents have access to what)
4. Enable AI to search, synthesize, and generate context
5. Interface with humans and other systems

This isn't vertical-specific; it's happening in sales automation, grocery shopping, meeting transcription, development workflows. The same fundamental architecture applied to different problem domains.

### Human as API Interface

With natural language interfaces to computers, humans have become indistinguishable from other system components. We have two primary interfaces:
- **Input**: Voice (speaking to computers; 10-20x more efficient than typing)
- **Output**: Text scanning (skimming and reading at variable depth)

The keyboard is obsolete for ideation. When typing, humans simultaneously compress ideas to fit the medium and the recipient, losing latent knowledge. Voice dumps the full brain state; AI can then compress and format for specific recipients and mediums.

### The ExoBrain Architecture

Personal computers reimagined as idea interfaces:
- **Local hardware control**: Personal or work devices running cutting-edge AI locally (frontier models from 5 years ago become $100 home devices)
- **Stripped-down OS**: Something like Linux AI; bare Chromium on hardware, no traditional application model
- **Plugin-based connectivity**: Gmail plugin, Twitter plugin, personal plugins for family/colleagues; humans become plugins
- **Idea spaces**: Chunks of your brain living in structured spaces, continuously updated through natural language interaction
- **Bidirectional flow**: AI aggregates inputs (Twitter feed, emails, texts, questions from others), human populates idea spaces through voice, AI generates outputs (tweets, emails, book drafts, responses)

### The Daily Workflow

Morning routine: wake up to synthesized questions from your idea spaces. Speak answers. AI routes answers to relevant idea spaces, triggers content generation, pushes outputs to appropriate channels (social media, email, shared spaces).

When someone queries your idea space, it answers based on current state. Novel questions get routed back to you as prompts.

Work happens through voice ideation rather than Slack synthesis, code review, and document reading. The system handles aggregation; you handle ideation.

### Business Model

Local control with cloud services:
- Core system runs locally (complete ownership and control)
- Paid services: backup storage, frontier model access, additional compute, security sweeps
- Subscription model: access to other people's idea spaces (authors, experts, published knowledge)
- Plugin ecosystem: connect to any data source or output channel

### Technical Vision

Not installing apps; installing data connectors. The box is designed for information flow. Algorithms you control. Complete transparency in what's being sent where. Security and privacy as first-class concerns because you own the hardware.

## Open Questions

- How do shared idea spaces work technically? What's the security model for cross-network idea space access?
- What does the algorithm control interface look like? How granular does it need to be?
- Is the local hardware vision realistic, or will economics always favor centralized compute?
- How does this interact with existing social platforms? Do they become pure output channels, or do they resist?
- What happens to the concept of "applications" in this model? Do they disappear entirely?
- How do you handle version control and "changing your mind" within idea spaces? Recency bias vs. historical context?
- What's the transition path from current computing to this vision? Can it be gradual?
